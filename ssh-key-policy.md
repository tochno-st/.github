# Политика генерации и использования SSH-ключей

## 1. Тип ключа и алгоритм

По умолчанию используется **Ed25519**.

```
ssh-keygen -t ed25519 -a 100 -C "<email> <имя/ник>"
```

RSA 4096 допустим как fallback для систем, не поддерживающих Ed25519. Другие алгоритмы (DSA, ECDSA на слабых кривых) не используются.

## 2. Парольная фраза

Passphrase **рекомендуется обязывать** для персональных ключей: ключ без passphrase лежит на диске в открытом виде. Ключи в CI/CD данной политикой не регулируются.

## 3. Комментарий ключа

Комментарий обязателен и идентифицирует владельца: email/логин и имя или ник. Пример: `-C "ivan@example.com Ivan Petrov"`. Комментарий помогает при аудите и отзыве ключей в GitHub.

## 4. Ротация и срок действия

- Ротация ключей - **раз в год**.
- Внеплановая ротация - немедленно при:
  - утечке приватного ключа;
  - уходе сотрудника из команды/организации;
  - компрометации устройства, где хранился ключ.

При ротации старый ключ отзывается, генерируется новый, ссылки на него обновляются во всех используемых сервисах (GitHub, серверы).

## 5. Один ключ на устройство

- Отдельный ключ на каждое устройство (ноутбук, ПК, сервер).
- Ключи между людьми не пересылаются и не используются совместно.
- Отзыв или утечка одного устройства не затрагивает остальные.

## 6. Хранение и использование

- Приватные ключи **запрещено** коммитить в репозитории, класть в `.env`, пересылать в открытых каналах или загружать на чужие устройства.
- Публичный ключ (`id_ed25519.pub`) - единственная часть, которую можно публиковать и добавлять в аккаунты/серверы.

Проверка ключа на GitHub:

```bash
ssh -T git@github.com
```
